## G0 · 工程骨架跑通　`[x]`

**目标**：项目能编译、能打包、能进游戏加载，为后续所有工作提供地基。

**验收标准**
- [x] `gradlew.bat build` 产出 `build/libs/logiscope-0.1.1-1.21.1.jar`
      （mod_version 带 MC 后缀，见 `gradle.properties`；1.20.1 分支为 `logiscope-0.1.0-1.20.1`）
- [x] jar 内含 `META-INF/neoforge.mods.toml`、`.class`、`lang/*.json`
- [x] 元数据里的 `${}` 占位符被正确替换
- [x] **元数据文件编码为合法 UTF-8**（中文 description）
- [x] 游戏内模组列表能看到 LogiScope

**依赖**：无
**关键风险**：中文导致的编码损坏 —— 已在 `build.gradle` 里用
`filteringCharset = 'UTF-8'` 预先规避。

## G1 · 最小可用闭环　`[x]`

**第一轮实机通过**（逐条结论见 [`VERIFY-HISTORY.md`](VERIFY-HISTORY.md)）。

**目标**：把"按快捷键 → 选一个容器格 → 开始记录 → 看到实时数字"这条链路打通。
这是**整个项目风险最集中的一段**。

**验收标准**
- [x] 打开任意标准容器界面（原版箱子即可），按快捷键能弹出示波器面板
- [x] 示波器里列出该容器的所有槽位（**只列外部设备**，不含玩家背包），含物品名与数量
- [x] 点一个槽位 → 状态变为 `RECORDING`，实时值随物品变化而更新
- [x] 手动物品进出，实时值跟着变（验证数据是真同步的，不是缓存）
- [x] ESC / 再按一次快捷键收起面板 → 原设备界面回来，且**采样不中断**
- [x] 按快捷键之外的键不影响原界面的正常操作
- [x] **在搜索框里打字时绝不弹面板**（原版背包搜索框、JEI 搜索框均通过）
- [x] 默认键位 `F9`（功能键不产生字符）；长按不会把面板反复开关（连发去抖）

**依赖**：G0
**关键风险**：CP2（GUI 内按键拦截）、CP3（打开面板不丢菜单）

## G1.5 · 面板：可拖动的浮层 + 操作按钮　`[x]`

**第一轮实机通过**（按钮清单已随轮次扩充，现状见 README「按键与操作」）。

**目标**：面板是一个能拖到一边的小窗口，而不是盖住整个屏幕；常用操作都有按钮。

**验收标准**
- [x] 面板打开时，**原容器界面仍然完整可见**（不再整屏压黑）
- [x] 按住面板标题栏可以拖动，位置在关闭/重开后保持
- [x] 面板默认落在屏幕右上角，不压住居中的容器界面
- [x] 拖动会被限制在屏幕内，不会拖丢
- [x] 按钮：返回选格 / 暂停 / 继续 / 清空 / 关界面后继续检测（开关）/ 收起
- [x] 按钮在不可用时变灰（例如没有容器界面时"返回选格"不可点）
- [x] 槽位多于面板高度时可滚轮翻页
- [x] 操作有即时反馈（面板上方的临时提示 / 动作栏状态提示）
- [x] 拖动与点击的手感实机确认

## G1.6 · 面板外的鼠标交给容器　`[x]`

**第三 / 四轮实机通过。** 它是 G2 框选能成立的前提。

**目标**：面板只占屏幕一块，其余区域本来就该能操作容器 ——
这也是后面做"图形化框选待测区间"的基础。

**验收标准**
- [x] 点面板以外的位置 → 转交给被压住的容器界面（能拿起/放下物品）
- [x] 拖拽转发（原版快速合成 = 拖过一排格子平均分配）
- [x] 松手转发（不转的话容器的 quick-craft 状态会卡住）
- [x] 滚轮转发（部分模组的容器界面用滚轮翻页）
- [x] 背景容器界面的格子**重新有 hover 高亮**（自己补画，原理见 CP8 之二）
- [x] 背景容器格子**有悬浮提示**（同理补画，见 CP8 之四）
- [x] **光标上的手持物品重新渲染**（见 CP8 之四）
- [x] 点在面板上但没打中控件时不穿透到容器
- [x] **第三方搜索框守卫**：JEI 搜索框里打字不再弹面板
      （三层守卫，见 `bind/TextInputGuard`）
- [x] 守卫第 3 层的逻辑 bug 已修（第三轮 A7/A10/A12：打过一次字后快捷键永久失效）
- [x] 顺带：创造模式背包里按快捷键不再弹面板

**已知遗留**：容器的**键盘**操作（数字键换物、`Q` 丢弃、鼠标中键取方块）仍无效 ——
它们走 `hoveredSlot`，而背景层拿不到鼠标坐标（见 CP8）。要修得连 `hoveredSlot` 一起补。

**依赖**：G1.5

## G1.7 · 面板可以推出屏幕　`[x]`

**第三轮实机通过。**

**目标**：GUI scale 调大时逻辑分辨率可能只有 320 宽，而面板有一定宽度 ——
必须允许把它推出屏幕，否则永远挡着容器界面。

**验收标准**
- [x] 往左/右拖出屏幕时，至少留 `width/8`（最少 8px）能抓住
- [x] 往下拖出屏幕时，至少留标题栏那一条"拖动条"
- [x] 往上拖时停在屏幕顶部（不允许推到上方）
- [x] 面板越界后**收起再打开会贴回屏幕边缘**（防止它正好压在别的按钮底下点不到）

**依赖**：G1.5

## G1.8 · 面板可缩放 + 关界面时不留假断档　`[x]`

**本轮新增（随 G2 一起做）。** 两件事都是被 G2 逼出来的：

- 波形要放坐标轴、图例、框选，固定 272×190 根本画不下 → 面板必须能缩放
- 关容器界面的那一 tick 会凭空记一条 `no_data` → 波形上出现一个假的断口

**验收标准**
- [x] 右下角拖拽缩放，尺寸跨"关闭-重开"保持
- [x] 缩到下限后不再变小；波形区不够高时明确提示而不是画糊
- [x] 关界面的过渡 tick **不再产生假 no_data**
      （第五轮的做法是"沿用上一 tick 的观测值"；第十轮第三次修复改成**什么都不写** ——
      那一 tick 确实没观测到，画图层连线即可，见 `ARCHITECTURE.md` CP9 之一）
- [x] 真读不到时（区块卸载 / 多人）照样记 no_data —— 修的是假阳性，不是把断档藏起来
- [x] 上述行为逐条实机验证通过（第五 ~ 十轮，见 `VERIFY-HISTORY.md`）

**依赖**：G1.5

## G2 · 波形可视化　`[x]`

**目标**：把时间序列画成能"一眼看懂"的图。

**验收标准**
- [x] 实时滚动波形，横轴时间、纵轴数量
- [x] 采样点比像素多时按列取极值，尖峰不会被平均掉
- [x] 物品类型发生切换的时刻，波形**断开**而不是连线（差值无意义）
- [x] `no_data` 区间在图上表现为**空白断档**，而不是画成 0
- [x] 纵轴自动缩放，并显示 min/max 刻度
- [x] 挂机 10 分钟不掉帧（5000 采样点无问题）
- [x] 能在波形上用鼠标框选一段区间（依赖 G1.6 的鼠标转发）
- [x] **时间刻度 = 世界 tick**：`/tick rate` 调慢时数据仍正确（世界没走 tick 就跳过采样；速率单位 n/t，见 CP13）
- [x] 滚轮/按钮缩放（光标锚定，见 CP14）

**用户补充的两条（本轮一并做了）**
- [x] **出现新物品就自动成为一条新的数据线**，不同物品用不同颜色区分
- [x] **图例可点击**，用于开关某条数据线的渲染

**依赖**：G1
**实现说明**：见 `ARCHITECTURE.md` CP10–CP14。

## G2.1 · 模组机器的关界面跟踪　`[x]`

**第五轮实测暴露的边界**：精妙存储箱子、MEK 电炉在关掉 GUI 后全部 `no_data`。
根因是 `WorldProbe#readNow` 只认原版 `Container`，而这批模组的方块实体不实现它
（javap 反查实锤，见 `ARCHITECTURE.md` CP9 之二）。

**验收标准**
- [x] 读取路径加第二条：NeoForge `ItemHandler.BLOCK` 能力（先无方向，再按六面）—— 第六轮 M1/M2/M3 通过
- [x] 原版容器路径不受影响（Container 优先，capability 只兜底）—— 第六轮 M3 通过
- [x] **下标映射验证**（MEK 类槽位下标硬编码 0）→ 建探针瞬间服务端"内容指纹匹配"（CP9 之三）
- [x] 接缝处的"观测空档"语义：不垫值、不造假断档（CP9 之一）；**用户判定 1t 承载无需跟进**
- [x] **下标歧义警告**（重复下标场景）→ force 通知，绕过去抖；判据字段修正后按设计生效

**依赖**：G3（FOLLOWING 状态）、G2（波形让问题肉眼可见）
**遗留**：下标验证靠"建探针瞬间的内容指纹"，对**空格子**必然歧义（警告兜底）；
"多个格子装同种等量物品"的机器同样歧义。无 GUI 设备（机械手）已由准星入口覆盖（CP17）。
"按物品分组"是**派生视图**而不是存储结构 —— 存储层仍是扁平的环形缓冲，
环形覆盖 / 清空 / 断档判定因此只需写一遍（CP10）。

## G3 · 持久身份：跨界面重连　`[x]`

**第一轮实机通过**（D1–D11；多人 D12–D15 不作为当前目标）。

**目标**：关掉界面再打开，探针自动接回同一个容器格；关界面的空档也不丢时间轴。

**验收标准**
- [x] 探头目标能表示成「维度 + 方块坐标 + 槽位下标」
      （`ProbeTarget.dimension/pos` + `ContainerAnchor`）
- [x] 重开同一台设备时，自动识别并恢复记录（`Sampler#tryRebind`）
- [x] 关掉界面后按坐标继续检测，且**用户可选开关**
- [x] 单人：直接读集成服务端的方块实体，拿到真值
- [x] 多人：读不到就记 `no_data`，重开界面那一刻拿到真值，**跨空档的差值仍然有效**
- [x] 无法识别时明确提示（状态显示"已暂停（源丢失）"+ 动作栏提示），
      而不是静默记一堆空样本
- [x] 关界面的接缝处不再凭空产生 1 tick 的 `no_data`
      （第十轮第三次修复后接缝处**少 1~2 格观测**而不是补一个重复值 —— 更诚实，也更看不出，见 CP9 之一）

**依赖**：G1
**遗留**：坐标是靠 `PlayerInteractEvent.RightClickBlock` 推出来的，
**用快捷键开界面的模组推不出来**（锚点为 null → 只能暂停）。这是已知边界。

## G7 · 探针实例与多格监控　`[x]`

**第十轮完成，并经多轮实机验证**。核心：**面板的入口从"选一个格子"变成"管理一批探针"**，并且**一个探针可以同时监控多格**。

**验收标准**

*探针实例（需求 1）*
- [x] 打开面板不再是"列表选容器"，而是「＋ 创建探针」+「正在运行的探针」列表
- [x] 列表里点一行 = 选中它并去看它的图表
- [x] 每行末尾有**删除按钮**：停止监测 + **删掉这个实例的缓存**
- [x] 多个探针**同时**在监测（切走再切回来，中间那段时间的数据也在）

*选格页（需求 2）*
- [x] 点「创建探针」→ 新建实例 → 进入选格页
- [x] **主方案：可视化选格** —— 点「选择容器格」后光标禁用物品交互，只用于选格
- [x] 点到哪个格子就是哪个格子；**左键按住拖动，划过的格子都被选中**；**右键取消选中**
- [x] **支持多格同时监控**，记录结果为聚合：**按物品分别求和** —— 同种物品数量相加，不同物品**各自一条不同颜色的线**（规则见 `ARCHITECTURE.md` CP16）
- [x] 「一键清空选择」按钮
- [x] 点「完成」→ 进入图表页
- [x] 图表页的「选格」**回退到这个实例的选格页**，且**回显原来的勾选**
      （第一轮实测"再进去显示已选 0 格"，已修）
- [x] 探针列表每行以**方块名**开头（用户："前缀加一个这个方块的名字"）
- [x] 列表选格仍然保留（无 GUI 的设备只能走这条路）

*准星探测（需求 3）*
- [x] 没有容器界面时按快捷键：准星方块**有 GUI** → 打开界面 + 打开探针面板
      （第一轮实测：用 `getMenuProvider` 判"有没有界面"连原版熔炉都判不出来，
      已改成问"这个方块会不会消费右键"——见 CP17；顺带修掉"手持工具误触"的隐患）
- [x] 准星方块**是容器但无 GUI** → 自动进入这台设备的探针实例创建流程，且只能用列表选格
- [x] 准星上**没有方块实体** → 打开根目录，用于选择已创建的探针实例进行监测

**依赖**：G1（最小闭环）、G2（图表页）、G3（持久身份）
**实现说明**：见 `ARCHITECTURE.md` CP16（探针实例与多格聚合）、CP17（可视化选格与准星入口）
**历轮实机**：A–D 组全通过 + 压力测试通过；随后的六次修正全部验证通过
（断线规则 / 采样挂世界 tick / 配置上限 / 单 tick IO / 图例弹窗 / 读数瘦身）。
逐条根因与修法见 [`PROGRESS-HISTORY.md`](PROGRESS-HISTORY.md) 第十轮。

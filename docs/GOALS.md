# LogiScope · 项目分目标

每个目标都必须有**可验证的验收标准**。没有验收标准的条目是愿望，不是目标。

状态图例：`[ ]` 未开始　`[~]` 进行中　`[x]` 已完成　`[!]` 受阻

---

## G0 · 工程骨架跑通　`[x]`

**目标**：项目能编译、能打包、能进游戏加载，为后续所有工作提供地基。

**验收标准**
- [x] `gradlew.bat build` 产出 `build/libs/logiscope-0.1.0.jar`
- [x] jar 内含 `META-INF/neoforge.mods.toml`、`.class`、`lang/*.json`
- [x] 元数据里的 `${}` 占位符被正确替换
- [x] **元数据文件编码为合法 UTF-8**（中文 description）
- [x] 游戏内模组列表能看到 LogiScope

**依赖**：无
**关键风险**：中文导致的编码损坏 —— 已在 `build.gradle` 里用
`filteringCharset = 'UTF-8'` 预先规避。

---

## G1 · 最小可用闭环　`[ ]`

**目标**：把"按快捷键 → 选一个容器格 → 开始记录 → 看到实时数字"这条链路打通。
这是**整个项目风险最集中的一段**（四个关键路径都在这里）。

**验收标准**
- [ ] 打开任意标准容器界面（原版箱子即可），按 `O` 能弹出示波器
- [ ] 示波器里列出该容器的所有槽位，含物品名与数量
- [ ] 点一个槽位 → 状态变为 `RECORDING`，实时值随物品变化而更新
- [ ] 手动物品进出，实时值跟着变（验证数据是真同步的，不是缓存）
- [ ] ESC 关闭示波器 → 原设备界面回来，且**采样不中断**
- [ ] 按 `O` 之外的键不影响原界面的正常操作

**依赖**：G0
**关键风险**：CP2（GUI 内按键拦截）、CP3（替换界面不丢菜单）

---

## G2 · 波形可视化　`[~]`

**目标**：把时间序列画成能"一眼看懂"的图。

**验收标准**
- [ ] 实时滚动波形，横轴时间、纵轴数量
- [ ] 采样点比像素多时按列取峰值，尖峰不被平均掉
- [ ] 物品类型发生切换的时刻，波形**断开**而不是连线（差值无意义）
- [ ] 纵轴自动缩放，并显示 min/max 刻度
- [ ] 挂机 10 分钟不掉帧（目标 < 1% 帧时间）

**依赖**：G1
**现状**：火花线已实现（简易柱状图），需要升级为带坐标轴的正规波形

---

## G3 · 持久身份：跨界面重连　`[ ]`

**目标**：关掉界面再打开，探针自动接回同一个容器格。

**验收标准**
- [ ] 探头目标能表示成「维度 + 方块坐标 + 槽位下标」
- [ ] 重开同一台设备时，自动识别并恢复记录（可配置为自动/手动）
- [ ] 无法识别时明确提示，而不是静默记一堆空样本

**依赖**：G1
**关键风险**：vanilla 的 `AbstractContainerMenu` **不保存方块坐标**，
需要额外手段反推（客户端右键事件 / 屏幕类型判断）。
可靠性会因目标模组而异 —— 这是本项目最大的开放性技术问题。

**待决问题**
- 反推坐标用 `PlayerInteractEvent.RightClickBlock`（纯客户端侧能拿到吗）？
- 拿不到坐标时，退化为「菜单类型 + 槽位下标」的启发式匹配是否够用？

---

## G4 · 标注与差值计算　`[ ]`

**目标**：能在波形上做标记，并算两段之间的差值。

**验收标准**
- [ ] 单击波形打一个标记点，双击删除
- [ ] 标记显示：所在 tick、物品、数量
- [ ] 选两点 → 显示 Δ数量、Δtick、平均速率（物品/tick）
- [ ] 标记随记录一起导出

**依赖**：G2

---

## G5 · 导出与回放　`[ ]`

**目标**：记录能离开游戏继续用。

**验收标准**
- [ ] 导出 CSV：`tick,item_id,count`
- [ ] 导出 JSON：含探针信息、起止时间、标注
- [ ] 导出位置在 `.minecraft/logiscope/` 下，文件名带时间戳
- [ ] 能重新载入一份导出文件并在界面上回放

**依赖**：G1（可提前做，不依赖 G3/G4）

---

## G6 · 稳定性与性能　`[ ]`

**目标**：长时间挂机不崩、不卡、不乱。

**验收标准**
- [ ] 连续记录 30 分钟，内存占用平稳（环形缓冲不涨）
- [ ] 环形缓冲写满后，最旧样本被覆盖且界面不报错
- [ ] 玩家死亡 / 换维度 / 断线重连时，采样优雅暂停而非崩溃
- [ ] 与其他常见客户端模组（JEI、REI、Jade）共存无冲突

**依赖**：G1

---

## 目标依赖图

```
G0 骨架
 └─► G1 最小闭环
      ├─► G2 波形可视化 ──► G4 标注与差值
      ├─► G3 持久身份（独立技术难题）
      ├─► G5 导出与回放
      └─► G6 稳定性与性能
```

**并行建议**：G2 和 G5 互不依赖，可以同时推进。
G3 是独立的硬骨头，建议单独排期，不要和 UI 工作混在一起。

# LogiScope · 项目方向

> 给模组机器装一台示波器。

## 一句话

在任意模组设备的容器界面里按一个键，把某个容器格接到探头上，
**逐游戏刻记录里面物品的种类与数量变化**，然后把它画成可以看、可以标注、可以算差值的波形。

## 要解决的问题

玩大型科技整合包时，"这条产线到底有没有堵"、"这个中间产物是真的在堆积还是在周转"、
"为什么产量上不去" 这类问题，靠肉眼看物品栏数字是看不出来的：

- 数字在跳，但**看不出趋势**（是稳态波动还是单向堆积？）
- 想算吞吐率，得**手动掐表数数**
- 出了问题想复现，**当时的数字早就不见了**
- 多台机器对比？只能来回切界面凭记忆

LogiScope 把这些变成一条**时间序列**：看得见斜率、看得见拐点、能回放、能导出。

## 核心技术依据（项目能成立的原因）

**容器的内容已经同步到客户端了。**

玩家打开任意容器时，服务端会通过 `ClientboundContainerSetContentPacket` /
`ClientboundContainerSetSlotPacket` 把槽位内容同步下来，落在
`AbstractContainerMenu.slots`（public 字段）。

所以本模组：

| 不需要 | 说明 |
|---|---|
| ❌ 不发网络包 | 全程只读客户端已有的数据 |
| ❌ 不需要服务端安装 | `@Mod(dist = Dist.CLIENT)`，纯客户端模组 |
| ❌ 不需要对目标模组做适配 | 只要它用标准容器菜单，就自动支持 |
| ❌ 不注册任何物品/方块 | 没有新内容，零侵入 |

代价是**必须承认的边界**，见下一节。

## 边界（明确不做什么，比做什么更重要）

| 限制 | 原因 | 影响 |
|---|---|---|
| 只能在容器界面**打开期间**采样 | 界面一关，`containerMenu` 被替换，数据源消失 | 想长时间记录就要挂着界面 |
| 拿不到"设备内部逻辑" | 只读客户端同步结果，读不到服务端计算过程 | 只能观测输入输出，不能观测内部状态 |
| 自适应不了自绘界面 | 有些模组不用 `AbstractContainerMenu` 承载内容 | 这类设备的槽位在本模组看来是空的 |
| 数值有 1 个网络往返的延迟 | 同步本身有延迟 | 算精确速率时要记得这个偏差 |
| 不做任何自动化控制 | 本项目只观测、不干预 | 不是自动合成/物流调度工具 |

**这些边界不是缺陷，是"纯客户端 + 零侵入"这个定位的必然代价。**
把它们写在最显眼的地方，是为了在 vibe coding 时不被误判成 bug。

## 目标用户

- 玩大型科技整合包、需要**排查产线瓶颈**的玩家
- 做模组评测视频、需要**拿出客观数据**的内容作者
- 调机器时想**量化验证**自己的设计是否划算的玩家

## 成功标准

1. 在不装任何服务端模组的前提下，能对**任意**标准容器设备完成一次完整记录
2. 一次 5 分钟的记录，掉帧影响用户察觉不到（目标：< 1% 帧时间）
3. 记录的波形能被人一眼看出"在堆积"还是"在周转"
4. 数据能导出成 CSV，用 Excel / Python 继续分析

## 非目标（现在不考虑）

- 多人服务器的权限/反作弊适配
- 自动截图、自动报告生成
- 服务端侧的数据采集
- 支持 Minecraft 快照版

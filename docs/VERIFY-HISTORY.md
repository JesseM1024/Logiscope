## 二、历轮暴露的问题 → 根因 → 修法（压缩版）

### 输入层

| 现象 | 根因 | 修法 |
|---|---|---|
| JEI 搜索框里打字误触发快捷键 | 只判了 `Screen` 类型，没判"正在打字" | `TextInputGuard` 三层守卫（焦点文本框 / 编辑框类型 / 按键不产生字符） |
| 守卫第 3 层过度拦截 | 判据太宽 | 重做（第三轮通过） |
| `O` / `]` 与搜索框冲突 | `KeyMapping` 匹配不看修饰键；字母键会进文本框 | 默认改成 `F9`（功能键不产生字符，冲突通道从根上不存在） |

### 数据层

| 现象 | 根因 | 修法 |
|---|---|---|
| 关界面时冒出 1 tick 假 no_data | 异步管道的启动延迟，不是读取失败 | 第五轮先用"垫值"补上；**第十轮③改成干脆不补**（那一 tick 就是没观测到，画图层面连线，见 CP9 之一） |
| 模组机器关界面后全是 no_data | 精妙存储 / MEK 的方块实体**不实现原版 `Container`**，内容只在菜单打开时同步 | 走 NeoForge `ItemHandler.BLOCK` 能力，六方向回退查询（CP9 之二） |
| MEK 槽位下标全是 #0，跟错格子 | 它的 `InventoryContainerSlot` 构造把下标硬编码 0，客户端拿不到真下标 | 挂探头那一刻在服务端做"内容指纹匹配"验证下标（CP9 之三）；空格子必然歧义 → 弹警告 |
| 下标歧义警告没弹 | 被 40t 去抖窗口吞掉 | 重要警告走 `force` 通道，绕过去抖 |
| 采样不跟 `/tick rate`（调慢后仍每 0.05s 一条） | 时间戳用客户端节拍，与世界脱节 | 样本时间戳改用**世界 tick**；世界没走 tick 就跳过采样；速率单位改 `n/t`（CP13） |
| `tick rate 200` 采样 20t 一次、`tick rate 40` 记录 10t 错值 + 10t 虚线 | 客户端 `Level#getGameTime()` 是**错拍阶梯**（本地 +1，服务端每 20t 砸一次绝对值） | **两只钟拆开**：样本时间戳用服务端线程读的权威 `ServerLevel#getGameTime()`；读值新鲜度用客户端 tick（CP15） |
| 容器列表里混进玩家背包 36 格 | 只判了 `containerMenu != inventoryMenu`，挡不住 | 按 `slot.container == player.getInventory()` 排除（CP1） |

### 呈现层

| 现象 | 根因 | 修法 |
|---|---|---|
| 波形一条线都没有 | 数据线绘制路径的问题 | 第六轮修（B 组通过） |
| 缩放"多按几次才动" / "一格到头" / 冻结态滚轮跳回最新 | ① 平移右端钳到最新 ② 数据未铺满时窗口钳起点 ③ 滚轮 ×2 太猛 | **光标锚定缩放** + `userZoomed` 标志 + 步进 1.25×/1.5×（CP14） |
| 关界面那一 tick 的接缝 | 见上"假 no_data" | 第十轮③：不再补值 |
| 纵轴刻度数字画到 GUI 外面 | 8 位整数挤爆 34px 的轴 | 科学计数法 + 轴宽 46px + **步长顶到相邻标签不重复**（第十轮③） |
| 读数（框选 / 十字线）给的是 `1.79E6` | 短格式被用到了读数上 | 只有纵轴用科学计数法，读数一律精确整数（第十轮③） |
| 图表页「列表」按钮没反应 | `onChip` 里漏了 `"list"` 分支 | 补分支 |
| 再进选格页显示"已选 0 格" | 回填只在两条入口调用 | 抽 `enterPicker(probe)` 让三个入口共用 |
| 选格页右上角两句提示重叠 | 都画在同一行 | 删掉绿色的那句（信息在下方灰行里已有） |
| 探针名分不清是哪台机器 | 只有槽位 + 坐标 | `ProbeTarget` 增加 `deviceName`，列表行首显示方块名 |
| 20t 下偶发断线 + 断线后 1t 平台 | ① 时间戳会偶尔跳 2（客户端/服务端 tick 不锁相），旧规则"间隔>1 就断"把它当断档；② 异步读值被复用后贴上新 tick 标签 | 断线只由显式标记决定 + 同一次观测只写一遍（CP10 / 第十轮③） |
| 曲线在观测空档处"跨过去"（是连线，不是真实值） | 采样驱动是**客户端 tick**（每秒最多 20 次），世界每秒走 20 格还能更快 —— 两者节拍不锁相，客户端必然偶尔看不到中间那格 | **把采样挂到世界 tick 上**（`ServerTickEvent.Post` 里同步读），世界走一格记一格；`/tick rate 200` 就是 200 条/秒（第十轮④） |
| 存量恒定、但进出都在发生时看不到流量 | 从外部只能观测到"每格结束时的存量"，**同 tick 内一进一出互相抵消**，那个信息没留在任何一次观测里 | 提供**单 tick 净流量（IO）线**：单向流 / 不同 tick 的进出 / 成批交替都能看到真实吞吐；**同 tick 双向往返显示 0**，要看它得监控上下游容器（或做 mixin 级挂钩，未做）（第十轮⑤，CP18） |
| `/tick rate 200` 只有每 ~10 tick 一个采样点 | 客户端每秒只能观测 20 次 | 同上：采样点是服务端 tick，不再是客户端 tick（第十轮④） |
| 时间轴"秒"标签在 `/tick rate 200` 下差 10 倍 | 硬编码按 20 tick/s 换算（F16，当时接受） | 按真实 tick 速率换算（`Level#tickRateManager().tickrate()`，第十轮④） |

### 交互层

| 现象 | 根因 | 修法 |
|---|---|---|
| 多格装不同物品时显示"混合物品" | 第一版把不同物品合成了一条线 | **按物品分别求和**：同物品数量相加、不同物品各自一条彩色线（CP16） |
| 空手对准精妙存储 / MEK / 原版熔炉按 F9 打不开界面，反而进"无 GUI"分支 | `BlockState#getMenuProvider` **连原版熔炉都不覆写**，静态判据失效 | 改问"这个方块右键会不会**消费**交互"（`useWithoutItem(...).consumesAction()`），判为无界面时一个包都不发（CP17） |
| 手持扳手按 F9 可能误用工具 | `performUseItemOn` 里 `itemUseFirst` 抢在方块前面 | 同上：不预判就不发包；判定要发包前先只读反射检查物品是否覆写了 `onItemUseFirst` |

## 三、已接受的设计行为 / 已知限制（不再跟进）

| 项 | 现象 | 决定 |
|---|---|---|
| 接缝处的 1t 承载 | 关/开界面切换瞬间有 1 tick 的数据复用 | 第七轮 N1b：物理极限，**已接受**；第十轮③ 改成不补值，这个现象随之消失 |
| 面板打开时 `F1` 无效 | 按键被自己的界面接管 | 不修（收起面板即可） |
| 面板打开时按 `E` / 数字键 / `Q` / 中键对容器无效 | `Screen#keyPressed` 不处理背包键；那些走 `hoveredSlot` | 已接受（鼠标操作完全可用） |
| 多人下的记录 | 容器内容只在菜单打开期间同步 | 记 `no_data`，不作为当前目标 |
| 自绘界面模组的数值不对 | 该模组把内容放在自定义包里 | 暂不测 |
| 快捷键开界面 → 关掉后暂停 | 拿不到方块坐标（F5，已由 CP17 的准星入口缓解） | 暂不测 |
| 时间轴的"秒"标签按 20t/s 换算 | `/tick rate` 调慢后"秒"不准（tick 数是对的） | 已接受；速率 `n/t` 恒正确 |
| 多格监控时其中一格读不到 | 整条记 `no_data`（不按剩下的求和 —— 和偏小在图上看不出来） | 第十轮设计（CP16） |
| 选格模式下面板外鼠标全被吃掉 | 需求要的"禁用物品交互" | 第十轮设计（CP17） |
| 探针上限 16 个 | 每实例一份半小时缓冲 + 每 tick 一次异步读取 | 第十轮设计（`MAX_PROBES`） |
| ~~客户端每秒最多观测 20 次~~ | **第十轮④已解决**：采样改挂世界 tick，`200` 时每秒 200 条 | 保留一行只作历史记录 |
| 环形缓冲按**样本条数**计 | 多格多物品时一个 tick 占好几条 | 监控 3 格 3 种物品时 36000 条覆盖约 10 分钟（CP16） |
| 缓冲按**样本条数**算，且**一个实例的多种物品共用同一份** | 默认 `bufferSamples = 72000`（可配，改完立刻生效） | 20 t/s 单物品约 1 小时；200 t/s 约 6 分钟；同时有 3 种物品时每种只留约 1/3 |
| 同 tick 一进一出时 IO 线显示 0 | 可观测量的边界（CP18）：外部只看得到每格存量 | 不是"没有流量"；替代办法是同时监控上游 / 下游容器 |
| 物品种类超过 `maxItemKinds`（默认 256）时不画线 | 图例与派生数据的规模上限 | 数据照记、统计照算，面板显示 `+N 未显示` |
| 服务端跑不满目标速率时样本也少 | 采样节拍 = 世界**真实**流速 | 如实的：世界没走那么多 tick，就没有那么多样本 |
| 对着"会消费右键但不是开界面"的容器机器按 F9 | 只能先按"有界面"处理，40 tick 后兜底 | 那一次右键与玩家自己右键等价（CP17） |

## 五、怎么跑（每次都用同一套）

```bat
cd /d D:\dev\logiscope
gradlew.bat runClient
:: 或生成脱离 Gradle 的启动脚本（更适合反复重启）
gradlew.bat createLaunchScripts
build\moddev\runClient.cmd
```

**准备**：创造模式 + 一个**原版箱子 / 熔炉** + 一台**模组机器**（精妙存储 / Mekanism）
+ **一台没有 GUI、只有物品栏的设备**（机械手这类，测准星入口用）+ 几组物品。

## 六、发现问题时怎么反馈（三件套）

1. **复现步骤**（哪台设备、哪一格、按了什么键、点了哪里）
2. **游戏日志**（`run/logs/latest.log`）
3. **面板上的关键数字**：`状态` / `ticks N  no-data M` / `now` / `switch N  series M`
   —— 波形问题额外给**框选的区间**与统计块里的数字，那几行直接对应数据层，
   能立刻区分"数据错了"还是"画错了"。

模组兼容性问题额外给：**模组名 + 版本 + 是哪个槽位**（输入槽/输出槽/升级槽）。

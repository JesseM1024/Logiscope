## 怎么跑

```bat
cd /d D:\dev\logiscope
gradlew.bat runClient
```

或生成脱离 Gradle 的启动脚本（更适合反复重启测试）：

```bat
gradlew.bat createLaunchScripts
build\moddev\runClient.cmd
```

**准备**：创造模式 + 一个**原版箱子** + 一台**模组机器**（本轮用精妙存储与 Mekanism）+ 几组物品。

**当前 `run/mods/` 里装的**：JEI、Create 6.0.9、Mekanism 10.7.17（+Generators/Tools）、Pipez、
Sophisticated Core/Storage（1.5.20）—— 这套环境就是第五、六、七轮的实测环境。

> ⚠️ **快捷键**：代码里的默认值是 **`F9`**，但 `run/options.txt` 里存着你设的
> `key_logiscope.key.open_scope:key.keyboard.right.bracket` ——
> **实机生效的是 `]`**（存档优先于代码默认值）。下面的清单统一写作 `]`。

### 第六轮暴露的三个问题（本轮已修）

| # | 现象 | 根因 | 修法 |
|---|---|---|---|
| 1 | **框选四连败**（M12/M13/M14 按下即弹"这一区间没有数据"；M16"实时"按钮点不动） | `beginSelection` **先置 `selecting = true` 再调 `window()`**，而 `window()` 第一分支就是"框选中→返回锁住的窗口"——首次框选读到的是初始值 `{0,0}`，窗口被锁成 `[0,0]`。M16 是它的下游假象：永远进不了冻结态，「实时」按钮自然没有可见变化 | 先取窗口、再置位（`ScopeScreen#beginSelection`，教训已写进 `ARCHITECTURE.md` CP12） |
| 2 | **检测方法切换时 1~2t 抄数据**（M1）：1t IO 测试里脉冲被拉宽 | seed 把上一 GUI 值垫进缓存后，下一 tick 的 `latest()` 拿到的仍是 seed——旧值被续命 1~2 tick；且重开界面的切换 tick 什么都不记（时间轴断一格） | 过渡 tick **立刻发出异步请求**（真值最早下一 tick 接管，seed 退化为兜底）+ 重开界面时用世界侧缓存垫一格（`Sampler#enterFollowing` / `tickFollowing`） |
| 3 | **MEK 槽位下标全是 0**（M4）：关 GUI 后跟踪的是别的格子 | javap -c 实锤：Mekanism 的 `InventoryContainerSlot` 构造是 `super(emptyInventory, 0, x, y)`——**下标硬编码 0**；它包装的 `IInventorySlot` 是单槽接口、不带位置信息，客户端**拿不到**真下标 | 挂探头瞬间（GUI 开着、两侧内容同步）在服务端做**内容指纹匹配**验证下标；匹配有歧义（如空格子）→ 动作栏警告，不瞎猜（`WorldProbe#verifyIndex`，见 `ARCHITECTURE.md` CP9 之三） |

> 💡 M6（机械手等**无 GUI 设备**无法选格）：已记入后续路线——「准星强制探测」
> （按快捷键对**看向的方块**直接建立探头，不需要 GUI）。本轮按你的要求先不做。

### N1c「卸载后 no-data 不增长」——是测试方法问题，不是 bug

单人存档里，方块所在的区块**只有在走出"渲染距离 + 生成区块"之外才会真正卸载**。
走几十格可能还在范围内，服务端照样读得到 → no_data 自然不涨（这是对的，不是没修好）。

**可靠的制造卸载方法**：

| 方法 | 操作 |
|---|---|
| A（推荐） | 把渲染距离调到 2（选项→视频设置），然后走 5–10 个区块远 |
| B | 直接 `/tp <自己> 2000 64 2000`（跨度和视距无关，一定卸载） |
| C | 用世界边缘 / 海洋中央的箱子，走远 |

验证它确实卸载了：`F3` 打开调试屏 → 走远后看 `Chunk` 统计，或直接看 no_data 是否开始增长。

### A. 框选与实时按钮（第六轮 M12/M13/M14/M16 复验）

P1-P4成功，P5冻结后的滚轮不是左右平移，而是缩放到t=最新处。我希望冻结后的滚轮是将光标所在t值在图标上的位置不变，随后两侧进行缩放，如果在放大时缩到最小无法满足位置约束，就以数据结束、起始端点为准，类似视频编辑软件中的时间轨的操作。
另外，有时候滚轮或按钮放大缩小会不动，多按几次才能动，还有滚轮一下就放到最大、缩到最小的问题，尝试只更改坐标轴，不考虑里面线是否渲染的问题，进行合理的放大缩小反馈。

## 发现问题时怎么反馈

把这三样一起给出，定位速度差 10 倍：

1. **复现步骤**（哪台设备、哪一格、按了什么键、点了哪里）
2. **游戏日志**（`run/logs/latest.log`）
3. **面板上的关键数字**：`状态` / `samples X  no-data Y` / `now` / `switch N  series M`

模组兼容性问题额外给：**模组名 + 版本 + 是哪个槽位**（输入槽/输出槽/升级槽）——
下标验证是否命中是按内容唯一性判断的，歧义场景会弹警告。
波形问题：**框选出问题的区间**，把统计块里的数字念一遍——
那几行直接对应数据层，能立刻区分"数据错了"还是"画错了"。

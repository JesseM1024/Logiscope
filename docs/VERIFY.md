## 怎么跑

```bat
cd /d D:\dev\logiscope
gradlew.bat runClient
```

或生成脱离 Gradle 的启动脚本（更适合反复重启测试）：

```bat
gradlew.bat createLaunchScripts
build\moddev\runClient.cmd
```

**准备**：创造模式 + 一个箱子 + 几组物品（建议两组不同物品，比如铁锭和铜锭）。

**当前 `run/mods/` 里装的**：`jei-1.21.1-neoforge-19.21.2.313.jar`（测搜索框冲突必须要它）。

> ⚠️ **快捷键已改为 `F9`**（原来是 `]`）。
> 旧绑定会存在 `run/options.txt` 里并覆盖代码默认值 —— 已经帮你删掉了那行，
> 所以直接启动就是 F9。若在别的实例上测试，记得去「选项 → 控制」里确认一下。
> 想改回 `]` 也行，那样才会用到三层文本守卫（见第四节）。

## 一、历次结果汇总

| 轮次 | 结果 | 遗留问题 |
|---|---|---|
| **第一轮** | A–E 核心行为全部成立 | 1 个真 bug（JEI 搜索框）+ 2 条增强 |
| **第二轮** | 修复项 A8/A9/A11 通过，B 组新增行为通过 | 守卫第 3 层过度拦截（A7/A10/A12 失败） |
| **第三轮** | 全部通过，**只暴露 2 个根因** | 见下 |

### 第三轮的两个根因（都已修）

| 现象 | 根因 | 修法 |
|---|---|---|
| A7 / A10 / A12 失败：在搜索框打完字、失焦后，快捷键**永久打不开面板** | `TextInputGuard` 第 3 层用了**累计计数**（`preCount > postCount`）。被吃掉的字符会在差值上留下**永久的 +1**，之后每个未被吃掉的字符同时给两个计数各 +1 —— 差值只会原地保持、**永远不归零** | 改成一个布尔量：Pre 置 `true`，Post 真的来了就置回 `false`。这样它恰好等于"**上一个**字符有没有被吃掉" |
| B7 / B8 部分失败：能拿起物品、操作逻辑正常，但**跟随鼠标的物品图标和数字不见了** | 背景层是用 `Integer.MAX_VALUE` 当鼠标坐标渲染的 → `AbstractContainerScreen` 里"把手持物品画在光标旁"那段代码把它画到了屏幕外 | 在最顶层自己补画（复刻 vanilla 的 `renderFloatingItem`，见 CP8 之四） |

**结论**：第三轮之后，A–F 六组的功能行为全部达成。本轮另外把默认键位换成 `F9`，
从根上消除"打字误触发"这条冲突通道。

### 历史上明确接受、不修的项

| 项 | 现象 | 决定 |
|---|---|---|
| E8 F1 | 面板打开时 F1 无效 | 不修：按键全被自己的界面接管，收起面板即可 |
| F3 | 面板打开时按 `E`（背包键）没反应 | 预期：`Screen#keyPressed` 不处理背包键 |
| F7 | 面板打开时容器的**键盘**操作（数字键换物 / `Q` / 中键）无效 | 走 `hoveredSlot`，背景层拿不到鼠标坐标。鼠标操作已经完全可用；要修得连 `hoveredSlot` 一起补（CP8 待决问题 4） |
| F4/F5 | 某些模组 / 快捷键开界面时的兼容性 | 需要具体目标模组才能验，留到 G6 |
| D12–D15 | 多人 | 不作为当前目标 |

## 发现问题时怎么反馈

把这三样一起给出，定位速度差 10 倍：

1. **复现步骤**（哪一格、按了什么键）
2. **游戏日志**（`run/logs/latest.log`）
3. **面板上的三行关键数字**：`状态` / `samples X  no-data Y` / `now`

如果是按键/界面问题，再补一条：**当前绑定的键位是什么**（选项 → 控制里看）。
如果怀疑第三方搜索框没被拦住，把**那个搜索框所属模组的名字和版本**也带上 ——
`TextInputGuard` 里每支持一个搜索类模组都要单独加一个探针（目前只接了 JEI），见该文件注释。

## 怎么跑

```bat
cd /d D:\dev\logiscope
gradlew.bat runClient
```

**准备**：
1. 一个**有单向流量**的格子（例如：一条管道以 64/t 往容器里灌，或一台机器以 64/t 往外抽）；
2. 有条件的话再准备一个**一进一出各 64/t**的格子（存量恒定那种）—— 用来确认边界行为；
3. 一个会产生**多种物品**的格子（测物品种类上限用）。

**配置文件**：`config/logiscope-client.toml`；游戏内「模组列表 → LogiScope → 配置」也能改。

## 一、本轮改了什么

| 需求 | 落地 |
|---|---|
| 缓冲容量可配、默认 72000 | `bufferSamples`：**改完立刻生效**（`SampleStore#resize`，保留最新样本） |
| 探针上限可配（默认 16） | `maxProbes` |
| 每个实例的物品种类上限 256 | `maxItemKinds`：超出的种类照样记、照样进统计，只是不画线（面板显示 `+N 未显示`） |
| 监控每个物品格的**单 tick IO 量** | 每条数据线多一层 **IO（净流量）**：`flow(t) = 存量(t) − 存量(t−1)`，只在**相邻两格**之间算 |
| 图例里 IO 是物品的子级、可控制渲染 | 图例每个物品两格：父格（存量线）+ `IO` 子格（默认关）；IO 线用同色系浅一档 |

⚠️ **一条必须知道的边界**：一进一出发生在**同一个世界 tick 内**时，两者互相抵消 ——
"进多少 / 出多少"没有留在任何一次观测里（我们能观测的就是"每格结束时的存量"），
所以 **IO 线会显示 0**。单向流、或进出发生在不同 tick / 成批交替时，IO 线就是真实吞吐。
要看同 tick 双向往返，替代做法是**同时监控上游与下游容器**。

## 二、复测项（★ = 直接对应本轮改动，优先测）

### A. 配置与资源上限（★）

| # | 操作 | 期望 |
|---|---|---|
| ★Z1 | 游戏内打开「模组列表 → LogiScope → 配置」 | 能看到三项：`bufferSamples` / `maxProbes` / `maxItemKinds`，都有注释说明 |
| ★Z2 | 记录中把 `bufferSamples` 从 72000 改成 300000（或反着改小），保存 | **不用重启、不用重建探针**：波形立刻按新容量走（容量变小时旧样本被裁掉，但**最新的一段还在**；`ticks` 计数与横轴随之变化） |

### B. 单 tick IO（★ 本轮核心）

| # | 操作 | 期望 |
|---|---|---|
| ★Z6 | 在**单向流量**的格子上开一个探针（例如 64/t 被抽出），点图例里物品后面的 `IO` 小格 | 出现一条**浅色**的流量线；数值在 −64 附近（抽是负、灌是正）；图上有一条 **0 基线** |
| ★Z7 | 把该物品的**父格（存量线）**点掉，只留 `IO` | 纵轴自动缩放到 IO 自己的范围 —— 流量看得清清楚楚（存量百万级时这是唯一能看清的姿势） |
| ★Z8 | 鼠标停在波形上 | 读数形如 `iron_ingot 1793280  Δ-64`（Δ 只在开了 IO 的物品后面出现） |
| ★Z9 | 框选一段有流量的区间 | 统计块那一行末尾多出 `in +x out -y`（区间内的流入 / 流出合计）—— 与 `Δ` 对照：无断档时 `in + out = Δ` |
| ★Z10 | 看面板 `now` 行 | 开了 IO 的物品后面跟 `[±n/t]` |
| ★Z11 | 让流量发生变化（把管道速率从 64/t 调成 32/t 或停掉） | IO 线**跟着变**（这就是"IO 速率也会变化"要的数据） |

## 三、报问题时的三件套

1. **复现步骤**（哪台设备、哪一格、`/tick rate` 多少、管线速率多少）
2. **`run/logs/latest.log`**
3. **面板数字**：`ticks N  no-data M` / `now` / `switch N  series M`（有未显示的会显示 `+N 未显示`），
   IO 相关的问题再补一句：**那条 IO 线当时是多少**（或把光标停上去读 `Δ`）。

## 怎么跑

```bat
cd /d D:\dev\logiscope
gradlew.bat runClient
```

或生成脱离 Gradle 的启动脚本（更适合反复重启测试）：

```bat
gradlew.bat createLaunchScripts
build\moddev\runClient.cmd
```

**准备**：创造模式 + 一个**原版箱子** + 一台**模组机器**（本轮用精妙存储与 Mekanism）+ 几组物品。

**当前 `run/mods/` 里装的**：JEI、Create 6.0.9、Mekanism 10.7.17（+Generators/Tools）、Pipez、
Sophisticated Core/Storage（1.5.20）—— 这套环境就是第五、六轮的实测环境。

> ⚠️ **快捷键**：代码里的默认值是 **`F9`**，但 `run/options.txt` 里存着你设的
> `key_logiscope.key.open_scope:key.keyboard.right.bracket` ——
> **实机生效的是 `]`**（存档优先于代码默认值）。下面的清单统一写作 `]`。

## 一、历次结果汇总

| 轮次 | 结果 | 遗留问题 |
|---|---|---|
| **第一轮** | A–E 核心行为全部成立 | 1 个真 bug（JEI 搜索框）+ 2 条增强 |
| **第二轮** | 修复项 A8/A9/A11 通过，B 组新增行为通过 | 守卫第 3 层过度拦截（A7/A10/A12 失败） |

### 第五轮的三个根因（本轮已修）

| 现象 | 根因 | 修法 |
|---|---|---|
| **图里没有任何线**（N2/N3），即使接上探头、GUI 开着 | `GuiGraphics#fill` 的颜色是 **ARGB**，调色板写成 6 位（`0x5DCAA5`）→ **alpha=0，完全透明**。`drawString` 有 `Font.adjustColor` 兜底（alpha 位为 0 就补 `0xFF`），`fill` **没有** —— 所以文字都看得见，线全被画没了。这个坑从第一轮的火花线（`0x9BE1CB`）就存在 | 调色板、空格子线、图例色块全部补上 `0xFF` alpha 位 |
| **模组机器关 GUI 后全部 no_data**（精妙存储、MEK 电炉） | `WorldProbe#readNow` 只认原版 `Container`。**javap 反查实锤**：Sophisticated Storage 的 `StorageBlockEntity` 与 Mekanism 的 `TileEntityEnergizedSmelter` 都**不实现** `net.minecraft.world.Container` —— 容器内容只在界面打开期间由菜单包同步 | 增加第二条读取路径：`Capabilities.ItemHandler.BLOCK` 能力（见 CP9 之二）。模组机器为了和漏斗/管道交互几乎都注册了它，服务端永远可查 |
| **N8 框选全部失败**（按下即显示"这一区间没有数据"） | 两个因素叠加：① 上面两条 —— 窗口里全是 no_data → 渲染器提前返回，**连选区都不画**；② 模组机器关 GUI 后没有真值，实时窗口（最近 20s）里自然没有数据 | ① 无数据分支也照样画选区；② capability 路径让窗口里有真值 |

> 💡 **N7 的"live 按钮无法点击"其实是同一件事**：窗口里没有数据，点 live 看不出任何变化。
> 线能画出来之后这个困惑会自己消失。

### N1c「卸载后 no-data 不增长」——是测试方法问题，不是 bug

单人存档里，方块所在的区块**只有在走出"渲染距离 + 生成区块"之外才会真正卸载**。
走几十格可能还在范围内，服务端照样读得到 → no_data 自然不涨（这是对的，不是没修好）。

**可靠的制造卸载方法**（第六轮 M5 用这个）：

| 方法 | 操作 |
|---|---|
| A（推荐） | 把渲染距离调到 2（选项→视频设置），然后走 5–10 个区块远 |
| B | 直接 `/tp <自己> 2000 64 2000`（跨度和视距无关，一定卸载） |
| C | 用世界边缘 / 海洋中央的箱子，走远 |

验证它确实卸载了：`F3` 打开调试屏 → 走远后看 `Chunk` 统计，或直接看 no_data 是否开始增长。

### N7f 的"重新启动后补上大段空白"是**设计行为**

暂停期间不采样 → 恢复记录后，暂停的那段时间就是一段**空白断档**（和 no_data 一样处理）。
连线跨过去等于编造数据。验收标准 N4b 写的就是这个。

### 历史上明确接受、不修的项

| 项 | 现象 | 决定 |
|---|---|---|
| E8 F1 | 面板打开时 F1 无效 | 不修：按键全被自己的界面接管，收起面板即可 |
| F3 | 面板打开时按 `E`（背包键）没反应 | 预期：`Screen#keyPressed` 不处理背包键 |
| F7 | 面板打开时容器的**键盘**操作（数字键换物 / `Q` / 中键）无效 | 走 `hoveredSlot`，背景层拿不到鼠标坐标。鼠标操作已经完全可用 |
| D12–D15 | 多人 | 不作为当前目标 |
| ~~F6~~ | ~~关界面那 1 tick 的假 no_data~~ | **第五轮已修**（N1/N1b/N1d 通过） |

## 发现问题时怎么反馈

把这三样一起给出，定位速度差 10 倍：

1. **复现步骤**（哪台设备、哪一格、按了什么键、点了哪里）
2. **游戏日志**（`run/logs/latest.log`）
3. **面板上的关键数字**：`状态` / `samples X  no-data Y` / `now` / `switch N  series M`

模组兼容性问题额外给：**模组名 + 版本 + 是哪个槽位**（输入槽/输出槽/升级槽）——
下标映射是否对得上是按模组逐一确认的。
波形问题：**框选出问题的区间**，把统计块里的数字念一遍——
那几行直接对应数据层，能立刻区分"数据错了"还是"画错了"。

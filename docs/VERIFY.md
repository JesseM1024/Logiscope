## 一、本轮改了什么

用户要求：**曲线不要跨过去，要每一格的真实值，并从根因修**。

| 现象 | 根因 | 改法 |
|---|---|---|
| 采样点之间会"跨过"没观测到的那一格 | 采样驱动是**客户端 tick**（每秒最多 20 次），世界每秒走 20 格（`/tick rate` 还能更快）——**两者节拍不锁相**，客户端必然偶尔看不到中间那格 | **把采样挂到世界 tick 上**：`ServerTickEvent.Post`（在 `tickChildren` 之后发）里同步读方块实体，时间戳取那一刻的 `ServerLevel#getGameTime()`。世界走一格记一格 |
| `/tick rate 200` 只能每 ~10 tick 采一个点 | 同上 | 现在**每秒 200 条**（服务端 tick 200 次 = `gameTime` +200） |
| 时间轴"秒"标签在 200t 下差 10 倍 | 硬编码 20 tick/s | 按真实 tick 速率换算（`Level#tickRateManager().tickrate()`） |

顺带删掉了整条异步读取管线（`request` / 缓存 / 新鲜度 / 去重）—— 采样点已经在服务端线程上，
"旧值贴新 tick 标签"这类问题结构上不可能再发生。

## 二、复测项（★ = 直接对应本轮改动，优先测）

### A. 采样密度：一个世界 tick 一条（★ 本轮核心）

| # | 操作 | 期望 |
|---|---|---|
| ★Y1 | 单人，`/tick rate 20`，挂一个每 tick 都在变的容器，看面板 `ticks N` | `ticks` 每秒涨 **20**（之前偶尔会少） |
| ★Y2 | 同上，把波形缩到很近（几十 tick 的窗口） | 相邻采样点**紧挨着**，**不再出现"跨两格"的长段**；曲线上是每一格的真实台阶 |
| ★Y3 | `/tick rate 200` 再测一次 | `ticks` 每秒涨 **约 200**；样本密度肉眼可见地变高 |
| ★Y4 | Y3 的窗口信息（右上角 `s / t`）与时间轴标签 | 秒数按**真实速率**换算：200t 下 200 个刻度 = `1s`（不再把 1 秒标成 10 秒） |

## 三、这条边界要知道（不是 bug）

| 项 | 说明 |
|---|---|
| 高流速下历史变短 | 缓冲按**样本条数**算（36000）：20 t/s 覆盖 30 分钟，200 t/s 只覆盖 **3 分钟** |
| 服务端跑不满目标速率时样本也少 | 采样节拍 = 世界真实流速（服务端跟不上就慢下来），这是如实的 |
| 模组机器的歧义下标 | 界面开着走菜单（一定对）；关掉界面靠指纹匹配（歧义时警告，可能读错格子）—— 见 `VERIFY-HISTORY.md` 的 CP9 之三 |

## 四、报问题时的三件套

1. **复现步骤**（哪台设备、哪一格、`/tick rate` 设成多少）
2. **`run/logs/latest.log`**
3. **面板上的关键数字**：`ticks N  no-data M` / `now` / `switch N  series M`，
   以及**右上角的窗口信息**（`x.xs / Nt`）—— 采样密度对不对，全靠它。

## 一、本轮改了什么

| # | 审查发现（P1） | 修法 |
|---|---|---|
| 1 | **IO 线统计吞掉每个数据段的第一笔真实流量、还谎报一次断档**（实测：存量 10→14→12 时 IO 报 `上升=0 断档=1`，存量报 `上升=4 断档=0`） | 那个 `breakBefore` 是**渲染**要的断线标记，统计不再拿它当"值不可信"：IO 的上升/下降/**变更事件照单全收**，缺口数改为"真的少了几笔 Δ" |
| 2 | NBT 数值窄化进 `int`：>2³¹ 回绕成负数、NaN → 0（都是"错值当真值"） | 越界/非有限一律按**读不到**处理（留空）；`Snbt` 不再接受 `NaN`/`Infinity` 字面量 |
| 3 | 纯数据探针**暂停不写 gap 标记** → 恢复后曲线跨过暂停连线 | 水位取"物品路 / 数据路"两条的较后者 |
| 4 | `configure()` 与在飞的服务端采样**竞态** → 新会话第一格写旧设备的值 | 采样在锁内**重取目标**并把守卫一起重算 |
| 5 | `readSlotAnchor` 把"设备早没了"也写成 0（一条永远为 0 的假曲线） | **方块实体类型比对**（C24-10）：还是那台设备 → 0；换了 → `no_data` |
| 6 | 跨世界静态残留：`ContainerAnchor.clearActive()` / `ProbeSlots.reset()` 有定义无调用 | 进世界（`LoggingIn`）与探针清空一起调 |
| 7 | 重命名框离开回放页不释放焦点 → **整个键盘被吞** | 按键入口按"页面还在不在"兜底清焦点 |
| 8 | `readHeader` 名义"只读几 KB"、实际整份解析（含几万条样本） | 改成**流式读**（`JsonReader`：认识的键取值，`samples` 整段跳过） |

**离线代理指标**（`dev-check/TestChart`，336 → **376 条**）：

| 断言 | 修复前 | 修复后 |
|---|---|---|
| 存量 10→14→12 的 IO 统计 | 上升 0 / 断档 1 / 事件 1 | **上升 4 / 断档 0 / 事件 2** |
| 中间断一次（104 缺格）再继续 | 上升 0 / 断档 2 | **上升 4 / 下降 −4 / 断档 1（真的那一次）** |
| `slot:NaN` / `slot:99999999999` | 被当成槽位号（0 / MAX_VALUE） | **不认这个列表**（宁可不识别，不给错号） |
| 存档头部读取 | 整份解析 | 流式（小结数值与写入一致，坏文件抛 `IOException`） |

### A. 数字对不对得上（★ 数据保真）

| # | 操作 | 期望 |

## 第十七轮①：上升/下降事件（★ 优先）

> **需求**：回放存档的「运算」弹窗里，在「变更区间」之后新增两项 ——
> **上升事件（Rise events）/ 下降事件（Fall events）**：只数增加 / 只数减少的事件。
> 数量线与 IO 线都可选。原理见 `ARCHITECTURE.md` **C19-6**，实现口径见 PROGRESS 第十七轮①。
>
> **准备**：一个存档回放（最好同时有**物品线**与 **IO 线**、且区间里有**升降交替**的一段；
> 另有一条**只升不降**的线更好，如灌装机累加）。

| # | 操作 | 期望 |
|---|---|---|
| ★N1 | 回放，框选一段**升降交替**的区间 → 运算选「上升事件」（数量线） | 首行 = `上升 N 次`，只数**增加**的那些变化；下方 `变化量 mean/var` 与 `周期 mean/var`；**周期 = 相邻两次上升之间的 tick 间隔**（不再是"两次任意变更"的间隔 —— 数值会与「变更区间」不同） |
| ★N2 | 同一区间切「下降事件」 | 只数减少的；变化量 mean 带负号；周期同理只看两次下降之间 |
| ★N3 | 换一条**只升不降**的线（数量线）选「下降事件」 | `下降 0 次`，**不出现** delta / period 两行（与「变更区间」count=0 的表现一致） |
| ★N4 | 同一区间对照三个运算 | `变更次数 = 上升次数 + 下降次数`（断档处三项都不计，仍应相等） |
| ★N5 | IO 线选「上升事件 / 下降事件」 | 与数量线口径一致；**段起点的第一笔流量照算**（不因断线标记被吞 —— 修复前的 IO 老问题别在新运算上复发） |

第十六轮：NBT 槽位型容器（MEK 那类）针对性探针 —— 按 NBT 自带的 slot 号监测

需求（用户）：MEK 物品格的 E 元素自带 slot 号（item[0].slot / item[0].item.count /
item[0].item.id），槽位是"通过 slot 特殊计算"的；希望针对这类容器写专门逻辑，
覆写打开/关闭 GUI 两种情况：点到某格就只监测 NBT 里对应 slot 的值；
空格子在 NBT 里没有元素、拿不到 slot 号 → 就不选它。

实现（NBT 是唯一权威）：
- 新纯类 analysis/NbtSlotLayout：识别"复合列表 + 每个元素都带数字 Slot 字段 +
  （内部或同级）有 id/Count"的布局；空列表 / 只有 Count / 流体列表都不误判
- 拾取：选格页每 20 tick 抓一次方块 NBT（单人直读、不花权限）并检测；命中这类容器时，
  点到的格子按"物品 id + 数量"反查 slot 号 —— 唯一命中才采用；
  空格子（无元素）与同物品同数量命中多格（分不清）都不选，并提示跳过了几个
- 存储：DataTarget 增加 nbtSlot（-1 = 普通路径目标）+ DataTarget.slotAnchor(...)；
  这类目标不生成任何 SlotRef，所以是"纯数据探针"，采样完全不碰菜单
- 读值：DataProbe.readSlotAnchor —— 读方块 NBT → 解析 → 找 slot == n 的元素 → Count/id；
  GUI 开关走同一条路（不再有"开界面 2 个、关界面 8 个"）；元素不存在 = 数量 0；
  设备整块读不到才是 no_data
- 文档：PROGRESS 第十六轮、ARCHITECTURE CP24（NBT 槽位锚点契约）、
  VERIFY 新增 G6-B4（Y1–Y8）、VERIFY-HISTORY 补行；
  顺带修掉 ARCHITECTURE 里 CP21 重复段与丢失的 CP23（结构复原为 CP20–CP24）
